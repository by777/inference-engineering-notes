① 动态 shape：默认保持动态，不会被焊死
==================================================================
  原始 : ['Shape', 'Gather', 'Concat', 'Reshape', 'Identity']
  化简 : ['Shape', 'Gather', 'Concat', 'Reshape']
  输入第 0 维 = 'batch'   ← 应该是 'batch'（字符串），不是数字

  用不同 batch 跑化简后的模型:
    batch=1: 跑通, max|diff|=0.0e+00
    batch=3: 跑通, max|diff|=0.0e+00
    batch=8: 跑通, max|diff|=0.0e+00

  → 结论：默认不碰动态维。这是正确行为，因为化简不该改变模型契约。

==================================================================
② overwrite_input_shapes：一旦指定静态，就永久焊死
==================================================================
  原始 : ['Shape', 'Gather', 'Concat', 'Reshape', 'Identity']
  overwrite 后 : ['Reshape']
  输入第 0 维 = 1   ← 从 'batch' 变成了 1

  用不同 batch 跑「被焊死」的模型:
    batch=1: 跑通
    batch=3: 失败 -> [ONNXRuntimeError] : 2 : INVALID_ARGUMENT : Got invalid dimensions for input: X for the following indices

  → 结论：这个参数是「性能 vs 通用性」的开关。
     固定 batch 的边缘部署可以加，通用服务绝对不能加。
     注意它只在「你显式传了」时才动手 —— 默认什么都不做。

==================================================================
③ 自定义算子：只能清两端，不能穿透
==================================================================
  原始   : ['ai.onnx:Identity', 'my_domain:MyAdd', 'ai.onnx:Mul', 'ai.onnx:Div', 'ai.onnx:Identity']
  化简后 : ['my_domain:MyAdd', 'ai.onnx:Mul', 'ai.onnx:Div']

  → 两头的 Identity 被删了（那是纯结构优化，不需要语义）。
     MyAdd 前后的 Mul/Div 一动不动（那是代数优化，需要语义）。

  为什么「不动」是对的：
    onnxsim 不知道 MyAdd 是幂等、可交换、还是有副作用。
    假设它错误地约掉 Mul/Div，而 MyAdd 实际会修改 k，结果就错了。
    所以它选择：不认识的算子 = 一堵墙。

==================================================================
④ 量化 QDQ：一个节点都不碰
==================================================================
  原始   : ['QuantizeLinear', 'DequantizeLinear', 'Mul', 'Div']
  化简后 : ['QuantizeLinear', 'DequantizeLinear', 'Mul', 'Div']

  → 完全一致，一个都没动。

  为什么：q (scale) 和 zp (zero_point) 是量化语义的一部分。
    Mul/Div 看起来能约掉，但 Q 是『有损』的：
      float -> int8 -> float 会丢掉精度
    约掉 QDQ 就等于把量化模型变回浮点模型，数值完全不同。

  → 量化图的化简要用专门的工具（ORT quantization tool / NNCF），
     不能指望 onnxsim。

==================================================================
总结：四条边界背后的同一个原则
==================================================================
  onnxsim 只做「它能证明等价」的化简。

  能证明 -> 做
    Identity 删除、Cast 删除、常量折叠、Conv+BN 融合

  不能证明 -> 不做，并且这个「不做」是正确的
    动态维保持动态（改了契约就变了）
    自定义算子当墙（不知道语义）
    QDQ 不动（有损操作，约掉就变语义）
    (x*k)/k 不约（浮点下不等价）
